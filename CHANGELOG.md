- **Photogrammetry panels — normal host-parented windows, no longer always-on-top.** The launchers set the frameless flag with `ui.set_flags(FramelessWindowHint=True)`, which *OR-ed* `FramelessWindowHint` onto a `QMainWindow`'s default flags — leaving the native title-bar decoration hints (`WindowTitleHint`/`WindowSystemMenuHint`/`WindowMinimize`/`Maximize`/`CloseButtonHint`) set. On a frameless window that the external-app handler parents under a DCC host (Maya), that combination makes the owned window float **always-on-top** of its parent. uitk's own editor windows (`WindowPanel`/`EditorPanel`) avoid this by setting a clean `Qt.Window | Qt.FramelessWindowHint` (no decoration hints, no `WindowStaysOnTopHint`). The three photogrammetry launchers (Metashape / RealityScan / Brush) now set the same clean flag set wholesale (`ui.setWindowFlags(Qt.Window | Qt.FramelessWindowHint)`, exactly as `WindowPanel` does) instead of OR-ing the frameless hint onto the defaults, so their flags match the reference exactly (`0x801`) — a normal frameless window. Parenting to Maya was already correct and needs no extapps change (it's app-agnostic: `ExternalAppHandler._prepare_in_process` reparents the panel to `self.sb.parent()`, the host main window, with `Qt.Window`). New `test_photogrammetry_window_chrome.py` pins all three panels to the live `WindowPanel` flag set (and asserts: type `Qt.Window`, frameless, not on-top, decoration hints cleared) so the drift can't return.

Encodes the hard-won fix: **never pass `-platform offscreen`** (Metashape doesn't bundle that Qt plugin — it crashes); the default `windows` platform initializes fine for a headless script even with no interactive desktop, and the license activates. `run_combined()` drives this package's runner headless from a remote/SSH caller — and because `metashape.exe -r run_combined.py` executes the file as `__main__` with **no package context** (so package-relative imports would `ImportError`), `run_combined.py` now self-bootstraps: run as a top-level script it puts the package roots on `sys.path` and switches to absolute imports (the `python -m` path is unchanged). Tests: `test/test_metashape_connection.py` (incl. a regression that executes the runner standalone).
  - **`RealityScanConnection`** (`realityscan_workflow._realityscan_connection`) — encapsulates RealityScan 2.0's reality: it is **window-station bound + Epic-sign-in gated**, so it will not process in the non-interactive session 0. The connection runs the CLI directly when interactive, else launches RC into the **active console session** via `AppLauncher.launch_in_session` (PsExec), recovering the exit code through a done-marker + poll; with no logged-in console it raises `RealityScanInteractiveError` instead of hanging (+ `epic_signin_active()` diagnostic). The interactive path routes through `AppLauncher.run(..., output_file=log)` (the ecosystem subprocess boundary — never raw `subprocess`); the non-interactive wrapper bat captures the exit code with a **leading-redirect** marker line (`>"marker" echo %errorlevel%`) — the obvious `echo %errorlevel%>marker` expands to `echo 0>marker`, where cmd binds the bare digit as a file-handle redirect and writes an empty marker, misreading every successful run (exit 0–9) as failure. `_run_rc` now delegates to it and **drops the unvalidated `-headless` flag** (the working RealityScan 2.0 invocations omit it; the connection handles interactivity). Tests: `test/test_realityscan_connection.py` (incl. a guard on the marker form).

- **Shared `PrepStagesMixin` — the RC↔Metashape prep stages are now one implementation.** `curate_input_set` and `equalize_exposures` were byte-for-byte duplicated across `realityscan_workflow._realityscan_workflow` and `metashape_workflow._metashape_workflow` (which is what let them silently diverge). - **Photogrammetry input prep improved after profiling the real 1,174-frame the test capture set.** Inspection found motion-blurred frames passing through (curation's sharpness floor was disabled), exposure equalization flattened to a 5-point luma spread and pinned to the first capture's cast, and no EXIF/strong wide-angle distortion. The new pythontk `ImageCurator.sharpness_floor_percentile` + `ExposureEqualizer.strength`/`reference_strategy` are plumbed through **both** engines (the RC↔Metashape mirror is preserved): `curate_input_set(..., sharpness_floor_percentile=...)` and `equalize_exposures(..., strength=..., reference_strategy=...)`. Both `run_combined` drivers default to the inspected-and-chosen settings — `--curate-sharpness-percentile 10` (drop the blurriest tenth, self-calibrating), `--equalize-strength 0.5` (preserve local contrast; RC re-balances during texturing), `--equalize-reference median` (no first-capture color-cast bias); the Metashape runner also gained `--keep-per-cluster` for full CLI parity. Identical defaults across both runners keep the 3-way comparison fair (engines receive the same prepped input). Verified on the real set: the p10 floor drops only the motion-blurred floor-pan frames; gentle/median equalization keeps per-clip luma spread at 5.7 (vs full-match's 0.1) while retaining contrast. **Note:** these stages silently warn-and-skip without `cv2`; install `opencv-python-headless` on the run host or prep is a no-op.
