- **2026-08-16 — The new CI gate's first real run went red: five tests encoded Windows semantics as universal.** Exactly what the gate was added to surface — the suite had never executed anywhere but a Windows workstation, so its platform assumptions were invisible. `publish` was correctly skipped, so nothing shipped. Three platform facts account for all five, and in each case the *production* code is right on both platforms while the test asserted one of them:

  - **A leading `/` roots a path on POSIX.** `_is_abs_dest` is deliberately stricter than `os.path.isabs` — a destination counts as absolute only with a drive/UNC (Windows) or a leading `/` (POSIX) — so `"/new/"` is the subdirectory `new` on Windows but the shared destination `/new` on POSIX. `test_folder_name_strips_typed_separators` now derives its expectation from `_is_abs_dest` instead of hardcoding `"new"`, and `test_matching_destination_folders_are_refused` spells its second field `"out/"` rather than `"/out/"` — a trailing separator is a typed spelling of the same subdirectory everywhere, so the guard under test can actually fire on both platforms.
  - **`os.path.normcase` is a no-op on POSIX.** `_stem_collisions` groups through it on purpose, for the same reason the destination guard does (documented at `slots.py:594`): `rock` and `ROCK` are one file on Windows and two on POSIX, so the collision is only real where the filesystem folds them. The test now gates that expectation on `normcase("A") == normcase("a")`.
  - **The `oem` codec is Windows-only.** The cross-session path writes a `cmd` `.bat` in the console OEM codepage and launches it via psexec — Windows-only by construction — so `LookupError: unknown encoding: oem` was the test running somewhere the mechanism cannot exist. Both cases are now `skipUnless(os.name == "nt")`.

  No source behavior changed. Suite: 597 passed / 8 skipped on Windows; the Linux run is what this commit is for.
